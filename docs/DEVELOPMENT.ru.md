# Для разработчиков

[English](DEVELOPMENT.md) · **Русский** · [← README](../README.ru.md)

PlayOS — приложение на Electron и TypeScript. Всё, что общается с системой, живёт в главном процессе: WinAPI через [koffi](https://koffi.dev), DualSense по HID и небольшой помощник на C# для громкости и яркости. Интерфейс — React 19 и [Motion](https://motion.dev).

## Быстрый старт

Нужны Windows 10 или 11, [Node.js 24](https://nodejs.org) и Git.

```bash
git clone https://github.com/fakem1nk/PlayOS.git
cd PlayOS
npm install
npm run dev
```

`npm run dev` запускает PlayOS с горячей перезагрузкой. Чтобы работать над интерфейсом без системной части, `npm run web` открывает его в браузере на `http://localhost:5199` с демо-данными.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Запуск с горячей перезагрузкой |
| `npm run web` | Интерфейс в браузере с демо-данными |
| `npm run typecheck` | Проверка типов всего проекта |
| `npm run build` | Сборка в `out/` |
| `npm run dist:setup` | Установщик в `release/` |
| `npm run build:helper` | Сборка `native/SystemHelper.cs` в `resources/PlayOSHelper.exe` |

Веб-превью понимает флаги в адресе: `?lang=en`, `?theme=light`, `?welcome` (первая настройка), `?update` (имитация обновления) и `#overlay` для меню в игре.

## Ключи облаков

Яндекс Диску и Google Drive нужны ключи OAuth-приложений. В репозитории их нет: релизные сборки берут их из секретов GitHub. Для локальной работы создайте файл `.env` в корне проекта:

```ini
MAIN_VITE_YANDEX_CLIENT_ID=...
MAIN_VITE_YANDEX_CLIENT_SECRET=...
MAIN_VITE_GOOGLE_CLIENT_ID=...
MAIN_VITE_GOOGLE_CLIENT_SECRET=...
```

Без него в настройках будет только папка синхронизации, остальное работает как обычно. Свои приложения можно зарегистрировать на [oauth.yandex.ru](https://oauth.yandex.ru) (доступ к папке приложения на Яндекс Диске) и в [консоли Google Cloud](https://console.cloud.google.com) (клиент «TVs and limited input devices» с областью `drive.file`).

## Как устроено

```
src/
├── main/                 Процесс Electron: всё, что общается с системой
│   ├── index.ts          Окна, оверлей, IPC, запуск
│   ├── launcher.ts       Запуск игр, учёт времени по процессу
│   ├── store.ts          Библиотека и настройки (library.json)
│   ├── steam.ts          Поиск установленных игр Steam
│   ├── pcsx2.ts, pine.ts Настройки PCSX2 и сохранения через PINE
│   ├── achievements.ts   RetroAchievements и достижения Steam
│   ├── media.ts          Поиск и загрузка обложек
│   ├── details.ts        Описания, HowLongToBeat, трейлеры
│   ├── gamepad.ts, hid.ts, win32.ts   XInput, DualSense по HID, WinAPI
│   ├── dsx.ts            Подсветка DualSense через DSX
│   ├── system.ts         Громкость, вывод звука, яркость
│   ├── cloud/            Облачные сохранения и синхронизация (см. ниже)
│   ├── updater.ts        Обновления из релизов GitHub
│   ├── backup.ts         Файлы копий .playos
│   └── log.ts            Журнал и отчёт об ошибках
├── preload/              Мост window.pcs между интерфейсом и системой
├── renderer/src/         Интерфейс на React: одна сборка, два окна
│   ├── App.tsx           Окно лаунчера
│   ├── OverlayApp.tsx    Окно меню в игре (#overlay)
│   ├── components/       Экраны и элементы управления
│   └── lib/              Ввод, пространственная навигация, звуки, темы, демо-API
└── shared/               Типы и переводы
native/SystemHelper.cs    Помощник Windows для громкости и яркости
scripts/                  Установщик, релизы и сборка
```

**Облачная синхронизация** (`src/main/cloud/`). Каждая выгрузка — неизменяемый снимок, а каждый компьютер пишет только свой маленький файл-указатель, поэтому два компьютера никогда не затирают друг друга. Синхронизация — трёхстороннее сравнение локального состояния, последнего синхронизированного и облачного. Если изменились обе стороны, выбирает пользователь. Пути хранятся с переносимыми метками (`%GAME%`, `%PCSX2%`, `%APPDATA%`…), чтобы сохранение встало на место на другом компьютере. Где игры PC хранят сохранения, берётся из [манифеста Ludusavi](https://github.com/mtkennerly/ludusavi-manifest).

### Договорённости

- **Размеры** в `rem`, где `1rem` — 1/108 высоты экрана. Макет под 1920×1080 одинаково выглядит на мониторе и на 4K-телевизоре.
- **Навигация** пространственная: всё с атрибутом `data-nav` доступно с крестовины (`lib/nav.ts`). Каждый новый экран должен работать только с геймпадом.
- **Переводы.** Строки оборачиваются в `t('…')`, ключ — русский текст, английский лежит в `src/shared/i18n-en.ts`. Каждой новой строке нужна запись там. В браузерном превью `window.__i18nMissing()` покажет, чего не хватает.
- **Без новых зависимостей** без веской причины. Звуки синтезируются в WebAudio, QR-код, чтение ZIP и YAML — свои.
- **Комментарии и тексты интерфейса** на русском, переводы строк LF.

## Pull request

1. Сделайте форк и ветку от `main`.
2. Одна тема — один pull request.
3. Перед отправкой запустите `npm run typecheck`. CI проверяет типы и сборку.
4. Для изменений интерфейса приложите скриншот или короткое видео, лучше в обеих темах.
5. Опишите, что изменилось и как вы это проверили.

Отправляя код, вы соглашаетесь, что он распространяется по лицензии [GPL-3.0](../LICENSE).

## Релизы

Поднимите `version` в `package.json`, добавьте заметки в `scripts/notes/<версия>.md` и отправьте тег:

```bash
git tag v1.0.1
git push origin v1.0.1
```

GitHub Actions соберёт установщик и создаст черновик релиза с заметками в описании. Мейнтейнер проверяет его и публикует. Установленные копии получат обновление сами.
